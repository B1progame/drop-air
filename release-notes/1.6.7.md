# Drop Air 1.6.7

Drop Air 1.6.7 makes nearby Wi-Fi discovery reachable from phones, fixes settings that appeared saved but did not persist, and reduces dashboard panel rendering work on slower devices.

## New

- Added a **Find devices** button to the transfer page, available on desktop and iPhone browsers.
- Added a browser-local display name for devices that connect from a phone browser.
- Added admin actions to restart Wi-Fi discovery and open Windows Firewall settings.
- Started Wi-Fi discovery for both the desktop app and the standalone Python server.
- Kept developer-machine settings out of the Windows installer.

## Fixed

- Fixed the nearby-device list being hidden in desktop transfer mode.
- Extended mDNS peer-cache expiry so quiet, healthy services are not removed after 12 seconds.
- Fixed upload-limit number validation blocking otherwise valid settings submissions.
- Made settings writes atomic and report persistence failures instead of returning a false success.
- Preserved unsaved settings fields when the admin status is refreshed.
- Reduced mobile drawer repaint pressure and restored touch scrolling inside the admin drawer.
- Corrected QR image accessibility text: Drop Air's local transport is HTTP, not HTTPS.

## iPhone and network notes

- iPhone browsers can browse Wi-Fi peers through the Drop Air host and request a connection. Bluetooth discovery is unavailable to this browser flow; transfers use Wi-Fi.
- The app serves local HTTP and does not have an SSL certificate acceptance flow. If Windows blocked local access, allow Drop Air on private networks in Windows Firewall and use **Retry Wi-Fi discovery**.

## Checks

- Python compilation and the Drop Air release UI test suite.
- Rendered inline JavaScript syntax check.
- Manual two-peer Wi-Fi discovery smoke check where multicast is available.
